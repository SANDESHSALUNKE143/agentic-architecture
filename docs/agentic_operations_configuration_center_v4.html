Security, approvals and data protection

Define guardrails that are enforced by the backend, not only by the UI.

Safe defaults
Human approval for external write actionsRequired for purchases, refunds, sending messages, or changing records.
Require approval for production data accessUse an explicit policy for sensitive or regulated datasets.
PII detection and redactionRedact sensitive data from prompts, logs, and traces where appropriate.
Prompt injection / untrusted content checksTreat retrieved documents and tool output as untrusted input.

UI toggles are not security controls until enforced by the API, tool gateway, identity provider, database permissions, and audit pipeline.
